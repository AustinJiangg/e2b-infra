# 01 · 沙箱、快照与回滚

> 「把一台正在运行的机器退回到十分钟前」听起来像科幻，其实是虚拟化里一个有几十年历史的老问题。
> 本篇讲这个需求从哪来、有哪几种做法、以及「快照」这个词在不同层次上各指什么。
>
> **读者**：所有人。**不要求任何预备知识** —— 不写代码也能读完。
> **接下来**：[第 2 篇 · microVM 与 e2b](02-microvm-and-e2b.md)。

---

## 0. 本篇要回答的问题

1. 什么样的需求会让人想「把机器退回到过去某一刻」？
2. 除了快照，还有别的办法吗？各自能做到什么程度？
3. 「快照」这个词在文件系统、容器、进程、虚拟机四个层次上分别指什么？
4. 我们这套东西在这个谱系里站在哪个位置？

---

## 1. 一个具体的场景

一个 AI Agent 接到任务：「把这个项目的测试跑通」。它在一个隔离环境（**沙箱**）里工作，
步骤大致是：

```
① 拉代码
② 装依赖
③ 改配置
④ 跑构建
⑤ 构建失败，看日志
⑥ 装一个缺的系统库
⑦ 改另一个配置文件
⑧ 跑构建 —— 现在连步骤 ④ 原来能过的部分都过不了了
```

第 ⑦ 步把环境搞坏了。Agent 需要回到第 ⑥ 步结束时的状态，换个改法重试。

### 1.1 「重来一遍」为什么不行

最直观的办法是：扔掉这个沙箱，起一个新的，把 ①–⑥ 重做一遍。三个问题：

| 问题 | 说明 |
|---|---|
| **时间** | 装依赖可能要几分钟。Agent 一次任务里可能要退十几次，累计代价不可接受 |
| **外部副作用** | ①–⑥ 里可能有不可重复的动作：调用了一个 API、写了一个数据库、消耗了一个配额 |
| **不可复现** | 依赖源的内容会变、网络会抖、时间戳会不同。重做出来的环境**不保证**和原来一样 |

第三条最要命：**如果重做的结果和原来不完全一样，那这次「回退」就没有意义** ——
Agent 面对的不再是「第 ⑥ 步之后的环境」，而是「一个大致像它的环境」。

### 1.2 这个需求的三个特征

- **高频**：不是一天几次，是一个任务里十几次；
- **低延迟**：回退发生在 Agent 的决策循环里，几百毫秒和几秒是完全不同的产品体验；
- **不能中断**：沙箱有 IP、有端口映射、有正在保持的连接、有外部持有的引用。
  中断一次，这些全要重建。

这三条决定了后面所有的技术选择。

---

## 2. 三种可选做法

### 2.1 重建沙箱

从头再来。上面已经讨论过 —— **慢、有副作用、不保证一致**。

### 2.2 应用层撤销

让每一步操作都记录一个「反操作」，出错时逆序执行。数据库的事务回滚就是这个思路。

问题在于**覆盖不全**。要撤销一次 `apt install`，得知道它装了哪些文件、
改了哪些配置、跑了哪些 postinst 脚本、往哪些数据库写了记录。而这只是一条命令。
Agent 会执行**任意**命令 —— 没有办法为「任意命令」写反操作。

> 一个更根本的问题：反操作本身也可能失败，而且失败时状态更乱。

### 2.3 虚机级快照

**不关心做了什么，只记录状态是什么。**

把整台虚拟机某一时刻的完整状态（内存、CPU 寄存器、磁盘、设备）保存下来，
需要时整体恢复。它不需要理解 `apt install` 干了什么 ——
它保存的是那条命令执行完之后**整台机器的样子**。

| | 重建 | 应用层撤销 | 虚机快照 |
|---|---|---|---|
| 能回退什么 | 一切（但结果可能不同） | 只有被显式建模的操作 | **一切** |
| 依赖对操作的理解 | 是 | **是** | **否** |
| 外部副作用 | 会重复 | 需要单独处理 | 不重复（但也不撤销） |
| 结果确定性 | 不保证 | 取决于实现 | **逐字节一致** |
| 典型代价 | 分钟级 | 毫秒～秒，取决于操作 | **看实现** —— 本书主题 |

> **注意最后一行的「外部副作用」**：虚机快照能把机器内部退回去，但**退不回外部世界**。
> 已经发出的 HTTP 请求、已经写进外部数据库的记录，快照管不着。
> 这是一条硬边界，任何快照方案都一样。

## 3. 「快照」在四个层次上

「快照」是个被复用得很厉害的词。四个常见层次，捕获的东西完全不同：

| 层次 | 例子 | 捕获什么 | **看不见**什么 |
|---|---|---|---|
| **文件系统快照** | LVM、ZFS、Btrfs 的 snapshot | 某一时刻磁盘上的文件 | 内存里的一切：进程、页缓存、未落盘的写 |
| **容器镜像层** | Docker 的 layer / commit | 文件系统的**变更集** | 同上，而且不含运行中的进程 |
| **进程 checkpoint** | CRIU | 一组进程的内存、寄存器、打开的文件、套接字 | 内核态的很多东西；**磁盘完全不管** |
| **虚拟机快照** | 本书主题 | guest 的**全部**：内存、vCPU、设备、磁盘 | 外部世界（对端、宿主、网络） |

### 3.1 为什么层次很重要

拿开头那个场景说：

- **文件系统快照**能把 `/usr/lib` 退回去，但退不掉一个已经加载了旧版本库的进程；
- **容器镜像层**能记录「装了什么」，但退不掉进程和内存；
- **进程 checkpoint** 能把进程树退回去，但**磁盘还停在未来** ——
  一个被退回的进程会读到它「还没写过」的文件；
- **虚机快照**能把这些一起退回去，因为它退的是**整台机器**。

第三条尤其值得琢磨：**内存和磁盘必须一起退，否则 guest 会看到一个自相矛盾的世界**。
比如文件系统日志里记着一笔已提交的事务，而内存里那个提交操作还没发生。
这个问题在[第 3 篇](03-snapshot-fundamentals.md)会展开。

### 3.2 代价的层次也不同

大致的量级感受（不是精确数字）：

| 层次 | 单次快照的典型代价 | 恢复的典型代价 |
|---|---|---|
| 文件系统快照 | 元数据操作，毫秒 | 毫秒 |
| 容器镜像层 | 秒～分钟（要打包上传） | 秒～分钟（要拉取解压） |
| 进程 checkpoint | 与进程内存成正比 | 与进程内存成正比 |
| 虚机快照（朴素实现） | 与**虚机内存**成正比 | 与**虚机内存**成正比 |
| **虚机快照（本方案）** | 与**改动量**成正比 | 与**回退跨度**成正比 |

最后一行就是这本书要讲清楚的事：**怎么让虚机级快照的代价从「与规格挂钩」
变成「与改动量挂钩」。**

---

## 4. 本方案的位置

一句话：

> **虚机级、进程内、高频、宿主本地。**

| 特征 | 含义 |
|---|---|
| **虚机级** | 捕获 guest 的全部状态，包括内存和磁盘 |
| **进程内** | 恢复时**不重建**虚拟机进程，往活着的进程里写回差异 |
| **高频** | 单次代价低到可以一个任务里用十几次 |
| **宿主本地** | 产物不进对象存储，随沙箱生命周期回收 |

第二条是这套方案最核心的选择，也是它与几乎所有现成实现的分野。
「进程内回滚」意味着：虚拟机的进程、它的 KVM 文件描述符、网卡、块设备、
以及**已经在物理内存里的整个工作集**，全部原样保留。恢复要做的只是
「把变了的那些页改回去」。

第四条是代价：产物离不开这个沙箱，所以**长期保存和跨机器迁移不归它管**
（[第 16 篇](16-lifecycle-and-portability.md)）。那些交给另一套机制。

---

## 5. 一点量级感受

用实测数字说明「与改动量挂钩」意味着什么（2 GB 内存的沙箱，鲲鹏 920B）：

| 操作 | 耗时 |
|---|---|
| 全量快照（第一次） | 1.549 s |
| 增量快照，**改动量 0 MB** | **0.022 s** |
| 增量快照，改动量 64 MB | 0.062 s |
| 增量快照，改动量 256 MB | 0.183 s |
| 恢复 | 几十毫秒量级 |

第二行最能说明问题：**什么都没改时，打一个快照几乎免费。**
朴素实现在这一行会付和第一行一样的 1.5 秒 —— 因为它不知道「什么都没改」。

> 完整口径与更多数字见[第 17 篇 §4](17-observability-and-verification.md#4-当前实测状态)。
> 950 上的数字口径不同，不能直接和这组比。

## 7. 小结

1. 需求来自一个很具体的场景：**Agent 执行任务时需要退回上一个已知良好的状态**。
   重来一遍在时间、副作用、可复现性三方面都不行。
2. 应用层撤销覆盖不全 —— **没有办法为「任意命令」写反操作**。
3. 虚机级快照的优势在于**不需要理解做了什么**，只记录状态是什么。
   代价是它退不回外部世界。
4. 「快照」在文件系统、容器、进程、虚机四个层次上捕获的东西完全不同。
   **内存和磁盘必须一起退**，否则 guest 会看到自相矛盾的世界。
5. 本方案是**虚机级、进程内、高频、宿主本地**。
   「进程内」是核心选择，「宿主本地」是它的代价。
6. 目标是把虚机快照的代价从**与规格挂钩**变成**与改动量挂钩** ——
   实测「什么都没改」时一次快照 0.022 s。
