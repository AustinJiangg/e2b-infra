## 2. 指标如何解释

| 指标 | 定义与用途 |
|---|---|
| 有效代码行（SLOC） | 按完整文件的语言词法识别，再统计差分中的代码物理行；空行、纯注释行、Python 的模块 / 类 / 函数 docstring 排除 |
| 新增 / 删除 | 两个端点之间新增和删除的代码行，用来表达修改范围；不逐提交累加 |
| 净增 | 新增减删除，表达本功能引入后的规模变化；重写同样长的代码可能净增为零 |
| 物理行 | Git 差分中的所有文本行，包含注释和空行；用于与 `git diff --numstat` 复核 |

一行同时有代码和注释时计一行有效代码；括号、声明、导入、Rust 属性、协议及配置中的非注释内容均计入。
字符串内的内容按宿主语言词法计数，不递归解析 Python 字符串中嵌入的 guest 程序，也不把长字符串拆成语句数。
这是有效**物理代码行**，不是语句数、机器指令数或覆盖率。

这里“当前累计净增”是源码相对开发前基线的增量，**不是运行组件完整源码的绝对行数**。
对新增功能文件，它对应当前保留的新增内容；对已有上游文件，它只反映修改后的净变化。
新增、删除和净增都受格式、重构、跨文件搬移影响，不能直接折算开发工时、个人工作量或代码质量。

### 2.1 生产、测试与生成代码的拆分

- Go `*_test.go`、Python SDK 测试及独立 FC 测试从生产实现中拆出。
- Rust `#[cfg(test)]` 模块按实际源码行范围拆出，字符串和注释中的括号不参与范围判断。
- 仅测试构建启用的 `rollback-fault-inject` 代码及两处 Cargo feature 声明列入测试支撑；Go 中默认编入服务的故障注入支持仍列生产。
- 自动生成的 Python RPC / protobuf 文件单列；生成 Go 模型中手工补充的 `DirtyBitmapPath` 字段按手写协议适配计，未把整个模型计入。
- 新增统计脚本、手册构建测试、本文、范围清单和统计 JSON 均属于文档制作材料，不进入回滚实现及测试主合计。

## 6. 复算与更新

源代码地图见 [附录 A](A-glossary-and-code-map.md)。统计材料都在部署仓库：

| 文件 | 用途 |
|---|---|
| `rollback/tools/code_stats.py` | 读取固定提交、拆分 Rust 测试、识别有效行、去重、汇总和更新正文统计块 |
| `rollback/stats/code_stats_scope.json` | 完整 SHA、逐文件类别、功能范围、测试用途及去重规则 |
| `rollback/stats/code-volume.json` | 归档汇总和逐文件新增 / 删除明细；是导读与本附录表格的共同数据来源 |
| `rollback/tools/requirements.txt` | 固定统计词法器 Pygments 2.17.2 和 HTML 构建依赖 |
| `rollback/tools/test_code_stats.py` | 多行注释与字符串、Python docstring、Rust 测试边界、端点差分与去重的回归检查 |

复算需要两个仓库均包含 §1 的 Git 对象，不需要切换工作分支，也不读取未提交修改。在 `e2b-infra` 仓库根目录执行；`--kasandbox` 可换为任意源码仓库位置：

```bash
python3 rollback/tools/code_stats.py \
  --kasandbox ../KASandbox_0904 --infra . --verify

# 修改范围清单并审查分类后，重算并同步正文数字
python3 rollback/tools/code_stats.py \
  --kasandbox ../KASandbox_0904 --infra . --update-docs

# 不需要源码仓库：只核对归档数据与正文是否同步
python3 rollback/tools/code_stats.py --check-docs

python3 rollback/tools/test_code_stats.py
```

复算会检查固定 SHA 的祖先关系、脚本范围是否完整、SDK 测试副本是否一致、每个文件的物理行是否与 Git 相符，
以及两阶段净增之和是否等于当前累计净增。遇到未分类文件即失败，不能自动把未知内容算入生产或测试。
HTML 构建会校验导读与附录统计块和归档一致；以后换版本时先更新范围清单、重算并复核，再更新手册版本和生成 HTML。
