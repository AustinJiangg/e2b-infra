# 附录 F · 代码规模

## 本章目标

给出进程级方案的代码规模：生产、测试、生成代码各多少，按组件怎么分。统计口径与沙箱级手册的
[附录 D](../../rollback/docs/D-code-size.md) 相同，两边的数字可以直接并列。

## 1. 什么叫“有效代码行”

简单说，就是**去掉空行和注释之后的代码行**，并且**只算我们改动的部分**：

- 只统计相对功能开发前基线的增量（新增、删除、净增）。上游原有、我们没改过的代码不算。
- 在这些增量行里，空行、纯注释行、Python 的模块 / 类 / 函数 docstring 都不算；一行里既有代码又有注释，算一行代码。
- 按完整文件的语言词法判断哪一行是代码，不是按行首字符猜。
- 新写的文件（如 e2b-infra 里的测试脚本）按全文计。

“物理行”是 Git 差分里的所有文本行，含空行和注释，只用来和 `git diff --numstat` 对账。

不计入：

- Markdown 文档、`go.sum`、内核 config（约两万行，是配置不是代码）、Terraform 与许可证文件；

内核补丁 `0002`、`0003` 按补丁里对 `.c` / `.h` 文件的增删行，用 C 词法计有效行。`0003` 是对 `0002` 的修复，它删掉的行计入删除，所以内核一项看净增。

## 5. 怎么复算

```bash
python3 criu-rollback/tools/code_stats.py --kasandbox ../KASandbox_0904 --infra .
```

在 e2b-infra 仓库根目录执行，`--kasandbox` 指向 KASandbox_0904 仓库。脚本只读上面固定提交里的 Git 对象，结果应与本附录逐项相同。
